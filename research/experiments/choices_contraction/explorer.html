Why the choice is forced

The term at exponent n is 1/(2ⁿ − 1). All later terms together are smaller. If the remainder is at least this term, take it. Otherwise skip it. A remainder strictly between the later tail and this term cannot be filled by any choices.

A restricted host allows only the exponents you selected. The same argument applies because removing terms can only decrease the later tail.

What is computed exactly?

Every comparison uses integer fractions, with JavaScript BigInt. The tail bound sums allowed terms through exponent 160 and adds 2/2¹⁶⁰ for everything beyond. For an exclusion, a shorter analytic bound is used when possible: 2⁻ⁿ + (2/3)4⁻ⁿ. No decimal approximation decides a result.

Where the evidence stops

A finite sum is an explicit answer. A strict gap rules the target out, even as an infinite sum. Reaching the chosen depth with neither event leaves the target undecided. Increasing the depth may change that answer.

This is an exact finite computation, not a Lean proof. It does not settle whether every infinite subseries sum is irrational, the unrestricted question in Erdős #257.

Check a terminal result yourself

Download the JSON and the independent Python checker. Run them in the same directory with Python 3.11 or later:

python3 -I verify_terminal_witness.py plectis-result.json

The checker reconstructs the forced choices and strict bound without importing this page or its producer. It deliberately refuses an undecided record; finite survival is not a certificate.

Keep exploring

Change the fraction, the allowed exponents, or the depth. The 189/388 example remains undecided through 16 and is excluded at 17. Try finding where another rational first encounters a gap.

The Python probe supports larger investigations. This page limits depth to 64 and input length to 256 characters to keep the computation responsive.
